# LanDrop 1.8.2 — secure Android restart

Android returns with a fresh private signing identity and the new orange icon.
The new application ID is `io.github.designer9999.landrop`; it installs alongside
the historical `com.landrop.app` Android application. Existing Android history
does not migrate automatically. Do not uninstall the old app until any important
history has been preserved. Future APKs signed with the new private key can update
the new installation normally.

The release APK targets arm64 devices, Android 7.0/API 24 and later. It uses the
optimized Rust release profile and Android release shrinking; this is not a debug
APK. APK signing is required by Android, regardless of direct GitHub distribution.
The compromised historical signing key is not reused. See the
[public signing fingerprint and custody notes](../../android/signing/README.md).

The desktop identity, updater endpoint and updater public key remain unchanged.
Desktop users can continue using **Check for updates**. The orange branding from
1.8.1 is retained on all targets.

Android-specific fixes include the desktop-only notification window call and
16 KB native-library alignment. Fresh-install receives use app-owned storage;
the Save action exports files through Android's supported storage APIs instead of
assuming unrestricted access to shared Downloads. Keep important files by saving
them to shared storage before uninstalling the app; app-owned history and received
copies are removed with the installation.

Selected documents with the same filename are staged separately so one cannot
overwrite another before sending. App-owned history previews and file opening
use narrowly scoped filesystem/provider paths.

Unused broad storage/media permission declarations and an unused legacy file
resolver are removed. Android HDPI launcher sizes are corrected, and the existing
TV launcher receives its required banner/optional-touchscreen metadata. Full
release lint passes without suppressions; remaining warnings and untested TV
navigation are recorded rather than presented as complete platform certification.
The native attachment helper now has its missing Android-only command permissions,
fixing the Save/Open authorization failure reproduced during release testing.
Android 8+ uses a full-bleed orange adaptive icon with the same cream speed-folder
mark, avoiding the small tile inside a white launcher circle. Android 13+ themed
icons use its matching monochrome layer when enabled by the user.

The local signed candidate is 13.13 MiB, approximately 24% smaller than the old
public v1.6.12 arm64 APK. Two isolated Android 16/API 36 emulators passed discovery,
bidirectional messaging, picker-to-file transfer, hash-verified Save, native Open,
in-place upgrade and restart-history checks. They ran the shipping ARM64 APK
through native translation; no physical-phone, native ARM64 performance, API 24–28
save-picker or 16 KB runtime coverage is claimed. Final public APK measurements
and verification are recorded separately.

Automatic Tailscale discovery in this release remains a desktop feature. Android
LAN discovery and messaging/file workflows must be distinguished from desktop
Tailscale support; installing Tailscale on a phone does not by itself make the app's
LAN multicast discovery work across a tailnet.

# 1.8.0-beta.2 — native, server-free Windows discovery

Execution date: September 18, 2026. Base source revision: `41bed30`.
Status: local implementation/testing; **not yet a public updater release**.

## What changed

Windows now discovers candidates from the installed Tailscale adapter's IPv4
host routes and receives native route-change notifications. It classifies Mullvad
service nodes through bounded, cached requests to Tailscale's local DNS. There
is no additional server, setup code, cloud token, LocalAPI request or Tailscale
CLI process. The rejected private-directory prototype is archived, not included.

Only a successful LanDrop handshake creates a live contact. Reciprocal, bounded
checks help discover a friend who opens LanDrop after already connecting to
Tailscale. LAN remains preferred for the same UUID, and saved history remains
separate from online presence. The compact UI is unchanged.

Windows socket source binding and route-generation checks prevent using stale
discovered routes. Incoming tailnet sockets must target the current Tailscale
adapter address. These are network-route checks, not cryptographic app pairing;
the legacy LAN framing and trust model remain unchanged.

The [implementation/research record](../windows-native-tailnet-discovery.md)
describes the exact boundaries, source links and Windows strong-host assumption.

## Runtime/performance and release limits

Windows does not poll Tailscale's process every 15 seconds. OS inventory uses
notifications plus a five-minute repair interval. Direct DNS classification is
bounded and cached; unresolved candidates have a smaller app-probe budget.
Established peers still use the existing 15-second application reachability
monitor. This is necessary background work, not zero idle activity.

No whole-application before/after performance benchmark was run. Prior
[performance measurements](../../PERFORMANCE_AUDIT.md) belong to 1.7.1. Build
duration and a local DNS helper test are not startup or user-interaction latency.

Automatic discovery currently requires the normal per-peer IPv4 host-route
layout. IPv6-only and aggregate `/10` configurations fail with a diagnostic; the
app never scans the entire CGNAT range. Tailnet policy and host firewalls must
allow the existing TCP port 29171. No VPN, DNS, Mullvad or firewall configuration
was changed during this work.

This beta must complete real two-device acceptance before being described as
fully tested worldwide support or promoted to a stable updater release. Local
unsigned packaging does not replace updater signing or operating-system signing.

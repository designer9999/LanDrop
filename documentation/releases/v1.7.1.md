# LanDrop 1.7.1 — Windows network safety patch

Automatic Tailscale discovery on Windows is temporarily disabled. The 1.7.0
poller could repeatedly activate and release the Windows user's Tailscale profile
when no persistent desktop client was connected. A status GET was incorrectly
treated as having no lifecycle side effects.

Windows LAN messaging/file sharing, compact device controls, history, native
notifications, and update handling remain available. This patch is containment,
not a claim that the user's separate Mullvad connectivity failure is resolved.

The remaining desktop discovery implementation excludes Mullvad service nodes
and adds conservative probe limits and retry backoff. A local diagnostic collector
can save results when internet access fails; it never invokes the Tailscale CLI,
changes VPN settings, captures packets, or uploads reports.

See the [incident report](../tailscale-incident-2026-09.md) and
[offline-capable diagnostics](../network-diagnostics.md). Do not reopen the
affected 1.7.0 build for testing without a deliberate, bounded test plan.

Local verification: 87 frontend tests, 51 Linux Rust tests, 52 Windows Rust tests,
strict Clippy, formatting, frontend production build, and diagnostic captures
with successful and deliberately failed HTTPS requests. Native Windows tests
include the no-client-query discovery guard. These are not a live Mullvad or
remote two-device acceptance test.

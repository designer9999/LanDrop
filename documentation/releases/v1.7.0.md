# LanDrop 1.7.0

LanDrop now discovers other running LanDrop desktops over an existing Tailscale
network as well as the LAN. A device found on both networks appears once, with LAN
preferred and Tailscale used if connection establishment fails.

## Changes

- Show only currently discovered peers at startup; keep saved conversations under
  **View all history**.
- Add Windows, macOS, and Linux Tailscale discovery and clear route labels.
- Remove stale peers even when mDNS does not report their departure.
- Preserve the current draft when another device sends a message or disconnects.
- Preserve attachments queued while an earlier file transfer finishes.
- Improve Material 3 controls, keyboard accessibility, dialog cancellation,
  screen-reader labels, reduced motion, and the minimum-window layout.
- Update compatible dependencies, Node 24, and Rust; restrict Tailwind scanning to
  frontend sources to reduce build overhead.

## Using Tailscale

Install this version on both desktops. Keep both Tailscale clients connected and
allow the intended peers to reach TCP port **29171** through their host firewalls
and tailnet access policy. LanDrop reads the installed client's status; it does not
change your login, server, or Tailscale configuration. Both devices must be awake
and running LanDrop. Automatic discovery currently supports desktop IPv4 peers.

See the [Tailscale guide](https://github.com/designer9999/LanDrop/blob/v1.7.0/documentation/tailscale.md).

## Compatibility and security

Existing saved history and device preferences are preserved. Older clients can
continue using the LAN protocol, but both endpoints need this version for the new
Tailscale discovery exchange. Interrupted transfers do not automatically resume.

Tailscale protects its tunnel. Direct LAN transfers still use LanDrop's plaintext,
unpaired protocol without final receiver acknowledgements. Use trusted networks
and deliberately scoped tailnet access. This release does not include a new
Android APK; Android publishing remains subject to the documented signing-identity
migration. Native OS code signing/notarization is separate from Tauri updater
signatures.

Local validation passed 63 frontend tests, 41 Rust tests, type checking, linting,
formatting, a production frontend build, and simulated-IPC browser checks. Actual
cross-site Tailscale transfers and upgrades on users' devices are not implied by
these local tests. Platform release-build results are available in GitHub Actions.

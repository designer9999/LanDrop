# LanDrop 1.8.0

## Automatic desktop Tailscale discovery

Open LanDrop on computers already connected to your tailnet. Windows now discovers
running peers through native adapter/route notifications and bounded application
checks, without an additional server, setup code, cloud token or Windows Tailscale
CLI/LocalAPI polling. Mullvad service candidates are filtered using cached local
Tailscale DNS responses. LAN remains preferred when both routes reach the same
device. Tailnet access policy and host firewalls must permit TCP 29171.

Saved conversations remain in history; historical devices are not automatically
shown as online. The compact device controls are preserved. This release also
includes the previously prepared desktop icon, Windows notification actions,
updater safety handling, and dependency security patches since public 1.6.13.

## Updates work through the existing app button

Use **Settings → About → Check for updates**. This release uses the existing
GitHub update endpoint and updater signing key. No new account or token is needed.
The release workflow publishes the update feed only after all required desktop
installers and updater signatures are present. Installation still requires your
approval; save or send drafts and let active transfers finish first.

## Verification and limits

The feature source passed GitHub frontend, Rust Windows/macOS/Linux, and security
checks. Local Windows verification passed 64 Rust tests, 87 frontend tests, strict
Clippy, formatting, and optimized installer packaging. Three additional native
checks exercised Windows inventory, local DNS, and provider startup/cancellation
without changing VPN settings. The release workflow repeats validation and builds
the signed updater artifacts for this version.

Two-physical-PC remote transfers, network switching and live Mullvad coexistence
have **not** yet been acceptance-tested with this implementation. Do not interpret
the automated checks as certification of every network configuration. Windows
discovery currently requires ordinary per-peer IPv4 host routes; IPv6-only or
aggregated-route configurations show a diagnostic instead of scanning a broad
address range. Existing LAN traffic uses the original unpaired protocol; UUID
matching is not cryptographic app pairing. Tailscale encrypts its own tunnel.

Desktop updater signatures are provided. Windows Authenticode and macOS
notarization are not configured, so OS trust warnings may still appear. Android
publication remains disabled, and automatic Android Tailscale discovery is not
included.

See the [native discovery record](../windows-native-tailnet-discovery.md) and
[pre-release verification](v1.8.0-beta.2.md) for the measured scope and limitations.

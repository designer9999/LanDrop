Mode or machine policy was changed. The local qualification copies the freshly
built native library into the isolated stage's `jniLibs` and runs Gradle with only

from the old generated Kotlin package were removed only in that staging tree.

invocation to avoid a C:-registry/D:-project path mismatch. These are local build
workarounds, not altered shipping runtime behavior.

An isolated Windows Node 24.18.0 protocol fixture sent a text message and a batch
of three files through emulator console redirection `tcp:39271:29171`. Two files

a 68-byte PNG. The shipping app rendered the text, both separate file cards and
the image in history. An early accessibility snapshot preceded settled rendering;
the repeated run and screenshots confirmed reception. Save/Open, export hashes,
restart persistence and app-to-app scenarios are recorded separately when complete.
No desktop app/profile or physical-device command was involved in these emulator tests.

The export test then exposed a real release blocker in the `4123786b…` candidate:
the full accessibility-tree error states that `plugin:file-helper|saveToDownloads`
is **not allowed by ACL**. Initial truncated screenshots made this look like a
missing handler; inspection of pinned Tauri 2.11.5 confirmed that mobile fallback
forwarding already exists, after the ACL check. The Kotlin implementation had been
registered, but its custom plugin commands had no permission manifest/grants.
Unit tests with mocked IPC did not establish this native authorization path.
That candidate must not be published or described as fully working. The replacement
adds an `InlinedPlugin` manifest with exactly `openFile`, `saveToDownloads` and
`getFileName` grants for the local Android main window. No wildcard/default grant,
remote-window capability, thumbnail command or callback grant was added. Independent
review and source-contract tests passed, as did native Windows formatting, Clippy
and tests. These checks were followed by actual export testing in the rebuilt
shipping release configuration below. Source absence of a grant is not represented
as a runtime denied-call test.

The fixed signed candidate `b5c62531…` subsequently installed **in place** on both

## Known coverage limits

No 16 KB-page device or API 24–28 SAF device test is yet claimed. Android automatic
Tailscale discovery is not implemented. Large-file sending still reads picked
content into JavaScript memory; the bounded streaming fix applies to **export**,
not the whole send pipeline. No application-wide performance improvement,
background-lifetime guarantee, Google Play qualification, or all-device guarantee
is inferred from unit tests or a successful build.

Remaining lint warnings include generated Tauri code style, unused generated
resources, dependency-update notices, vector wordmark path complexity and launcher
shape guidance. They were not hidden with a baseline or disabled checks. TV remote
navigation has not been tested. No claim that every dependency is the latest major
version or that Google Play's complete review requirements have been met is made.

Version-matched picker inspection: Tauri dialog 2.7.3 uses `ACTION_GET_CONTENT`
with `CATEGORY_OPENABLE`, not persistent `ACTION_OPEN_DOCUMENT` access. The fs
plugin opens the selected URI through ContentResolver; history is copied into
private storage before that temporary grant expires. No global storage grant is
needed for that import or for exporting app-owned files to MediaStore/SAF.

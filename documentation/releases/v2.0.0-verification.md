## Desktop (Windows 11, native)

A dev build under a separate identity (`com.landrop.app.devtest`, so the installed
app's history and settings were untouched) was driven over WebView2 CDP, with a
protocol-level simulated peer:

- v2 text, caption + image batch, reply, edit, reaction and delete were each
  acknowledged by the real backend and rendered correctly; a 1.8-style message
  arrived without an acknowledgement, as designed.
- Pasted image saved through a raw IPC body; thumbnail generated in ~100 ms and
  served from cache in ~4 ms; asset-protocol images load under the CSP; the media
  scope refused `C:\Windows\win.ini`; `javascript:` links were rejected.
- Copy image placed a 128×128 bitmap on the Windows clipboard (clipboard restored
  afterwards).

## Android (two API 36 x86_64 emulators, ARM64 translation)

Fresh AVDs on one emulated Wi-Fi network (`10.0.2.16` / `10.0.2.17`). The APK was
built locally, signed with the release key (certificate SHA-256
`ab80892384f01e61d3a1c6b9387f9c65111b46bccad383f254415c5f9e9c0c03`) and passed the
16 KB ZIP and ELF alignment gates.

1. Public 1.8.2 APK (SHA-256 `d7ebb54e…`, matches the release) installed on both;
   messages exchanged both ways to create history.
2. A upgraded in place to 2.0.0: history kept; 2.0 → 1.8.2 and 1.8.2 → 2.0
   messages delivered; the 2.0 sender showed a single ✓ (no receipt from 1.8.2).
3. B upgraded: 2.0 ↔ 2.0 message showed ✓✓ delivered; reaction, edit, delete for
   everyone, reply (including a quote of pre-2.0 history via the reply preview)
   synced; a photo with caption arrived as one message, opened in the viewer, and
   the Save export matched the original SHA-256 `64c2d577…cb3c` byte for byte.
4. Force-stop and relaunch kept messages, edits, reactions, the tombstone and the
   photo. The crash buffer had no LanDrop entries.

Defects found and fixed during this run: the keyboard covered the composer
(edge-to-edge IME insets, also present in 1.8.2); long-press started a native text
selection; peers found by the subnet scan showed `Device-xxxxxxxx` (also present in
1.8.2); quotes of messages the receiver lacks showed no text.

Not covered: physical phones, native ARM64 hardware, 16 KB-page devices, iOS,
Tailscale between real machines, and the macOS/Linux installers (built by CI).
